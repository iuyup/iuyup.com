# 为什么需要多智能体系统

单智能体在处理复杂任务时往往显得力不从心。当一个任务需要多种能力协作时，多智能体架构就显得尤为重要。

## 核心设计模式

我在 AgentFlow 项目中实现了 10+ 种多智能体设计模式，其中最常用的包括：

### 1. Supervisor 模式

一个主管智能体负责任务分解和分配，其他专业智能体负责执行具体子任务。

```python
from langgraph.graph import StateGraph, END
from typing import TypedDict

class AgentState(TypedDict):
    task: str
    result: str
    next_agent: str

def supervisor_node(state: AgentState) -> AgentState:
    task = state["task"]
    if "代码" in task:
        return {"next_agent": "coder"}
    elif "搜索" in task:
        return {"next_agent": "researcher"}
    return {"next_agent": "general"}
```

### 2. Sequential Pipeline 模式

适用于有明确执行顺序的任务，每个智能体处理一个步骤。

```python
def create_pipeline(agents: list) -> StateGraph:
    graph = StateGraph(AgentState)

    for i, agent in enumerate(agents):
        graph.add_node(agent.name, agent.process)

    for i in range(len(agents) - 1):
        graph.add_edge(agents[i].name, agents[i + 1].name)

    return graph
```

## 实践经验

> 不要过度设计。在开始时，一个简单的顺序执行链往往比复杂的网状结构更可靠。

### 状态管理

使用 `StateGraph` 时，状态的设计至关重要。建议：

- 明确每个字段的类型和用途
- 使用 `TypedDict` 定义状态结构
- 避免在状态中存储大型对象

### 错误处理

```python
from langgraph.prebuilt import ToolNode

tool_node = ToolNode(tools=[search, code_exec])

def safe_execute(state: AgentState) -> AgentState:
    try:
        result = tool_node.invoke(state)
        return {"result": result, "error": None}
    except Exception as e:
        return {"result": None, "error": str(e)}
```

## 总结

多智能体系统的核心挑战在于：

1. **任务分解** - 如何将复杂任务合理地划分为子任务
2. **智能体协作** - 如何设计智能体之间的通信机制
3. **状态同步** - 如何在多个智能体之间维护一致的状态
